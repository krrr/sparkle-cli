# 计划:非 Gemini provider 时自动回退到第三方搜索 API(首期 Exa)

## 背景与现状

`web_search`(`packages/core/src/tools/web-search.ts`)通过 Gemini API 的
`googleSearch`
grounding 实现搜索。当激活的 provider 是 OpenAI 兼容提供商时,`openAiCompatibleGenerator.ts:235-245`
会静默丢弃 `{googleSearch:{}}` 参数,工具返回无依据的"幻觉搜索结果"。

已确认的设计决策:仅自动回退(Gemini
provider 行为不变)、密钥存 settings.json(支持环境变量引用)、未配置时返回明确错误、Exa 结果用 highlights 要点形态。

## 改动方案

### 1. 配置项声明 — `packages/cli/src/config/settingsSchema.ts`

在 `tools` 对象(1462 行起)的 `properties` 下新增 `webSearch` 子对象:

```jsonc
// settings.json 目标形态
"tools": {
  "webSearch": {
    "thirdPartyProvider": "exa",   // enum,首期仅 "exa",可扩展
    "apiKey": "${EXA_API_KEY}"     // 明文,自动支持 ${VAR} 环境变量展开
  }
}
```

- `thirdPartyProvider`:enum,`options: [{label:'Exa', value:'exa'}]`,`requiresRestart: true`
- `apiKey`:string,`showInDialog: false`(避免明文密钥进设置对话框)
- Zod 校验由 `settings-validation.ts` 从 schema 自动生成,无需单独改
- 新增 provider 的扩展方式 = 加一个 enum 值 + 一个实现类(见第 3 步的工厂注册表)

### 2. 配置透传到 core

- `packages/core/src/config/config.ts`:`ConfigParameters` 新增
  `webSearchConfig?: WebSearchConfig`(新类型
  `{ thirdPartyProvider?: string; apiKey?: string }`),按现有模式加 private 字段、构造赋值、getter
  `getWebSearchConfig()`(参照 `coreTools` 的 546/715/950/1900 行链路)
- `packages/cli/src/config/config.ts`
  `loadConfig`(~902 行):`webSearchConfig: settings.tools?.webSearch`

### 3. 第三方搜索抽象 + Exa 实现(新目录 `packages/core/src/tools/websearch/`)

**`third-party-search.ts`** — 可扩展的核心:

```ts
export interface ThirdPartySearchResult {
  title: string;
  url: string;
  publishedDate?: string;
  highlights: string[];
}
export interface ThirdPartySearchProvider {
  readonly name: string;
  search(
    query: string,
    signal?: AbortSignal,
  ): Promise<ThirdPartySearchResult[]>;
}
// 工厂注册表:新增 provider 只需在这里注册一行
export function getThirdPartySearchProvider(
  config: Config,
): ThirdPartySearchProvider | null;
// 读取 webSearchConfig;密钥优先级:EXA_API_KEY 环境变量 > settings 值;未配置返回 null
```

**`exa-search.ts`** — 首个实现:

- `POST https://api.exa.ai/search`,`Authorization: Bearer <key>`
- 请求体:`{ query, numResults: 10, contents: { highlights: true } }`(Exa 官方对 coding
  agent 的推荐形态)
- 复用 `utils/fetch.ts` 的 `fetchWithTimeout`(超时 30s)+ `utils/retry.ts` 的
  `retryWithBackoff`(429/5xx 重试),参照 `web-fetch.ts:296-319` 与
  `openAiCompatibleGenerator.ts:282-308` 的模式
- 错误处理:非 2xx 抛带 status 的 Error;abort 透传 signal

### 4. `web-search.ts` 执行分支(核心改动)

在 `WebSearchToolInvocation.execute()` 开头(88 行附近),参照
`web-fetch.ts:789-803` 的先例:

```ts
const authType = this.context.config.getContentGeneratorConfig()?.authType;
if (authType !== undefined && authType !== ProviderType.USE_GEMINI) {
  const provider = getThirdPartySearchProvider(this.context.config);
  if (!provider) {
    return 明确错误 ToolResult(ToolErrorType.WEB_SEARCH_FAILED):
      "当前 provider 不支持 Google Search grounding,且未配置第三方搜索 API
       (tools.webSearch.thirdPartyProvider + apiKey)"
  }
  const results = await provider.search(this.params.query, signal);
  return {
    llmContent: 格式化 markdown(每条结果:标题/URL/日期 + highlights 要点列表),
    returnDisplay: 'Search results returned.',
    sources: results.map(r => ({ web: { uri: r.url, title: r.title } })),  // 保持 GroundingChunkItem 形状,下游 UI 兼容
  };
}
// Gemini provider:原有 grounding 路径完全不动
```

abort 与异常处理沿用现有结构(cancelled / WEB_SEARCH_FAILED)。
